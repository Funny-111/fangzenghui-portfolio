## 01 电商问数 · NL2SQL

面向电商业务人员在多表、多指标场景下取数靠提需求、口径难对齐、结果不可信（慢 / 偏 / 黑盒）的问题，建设自然语言问数系统。以 Prompt 行为合同、分层检索与三层评测门禁，将人工取数升级为可解释、可拒答、可回归的自助取数能力。

- **Prompt 行为合同化**：针对模糊问题硬凑口径、超范围问题越权取数（偏 / 漏），通过生成 / 澄清 / 拒答三形态输出契约，将「模型尽量作答」升级为「该澄清就澄清、该拒答就拒答」，降低错答与越权风险。
- **分层检索与强绑定生成**：针对表 / 字段 / 指标 / 取值分散、自然语言到 SQL 口径漂移（散 / 漂），通过三库元数据（表字段库 / 指标库 / 真实取值库）按 Dify 知识库规范整理并多路召回，将自由生成升级为带证据约束的 SQL 生成；结果卡展开 SQL、命中字段与置信度，业务侧可自行判断数据能否采信。
- **评测驱动的验收门禁**：针对生成型系统质量不可观测、改动易回归（黑盒 / 难回归），通过 100 条三层评测集、点踩归因三分类（召回 / SQL / 理解）与 badcase 回流，将「凭感觉上线」升级为「过门禁才放量」。
- **模型选型的成本决策**：针对准确率、延迟、成本三者互相拉扯，通过 MiMo 与 DeepSeek 三维对照实验 + 三层回归测试，把选型从拍脑袋升级为有数据依据的换模型决策。

**成果**

- 效果：SQL 正确率从首跑 57% 修复至 97%，越权 0。
- 能力沉淀：100 条三层评测集、13 个阶段的可复用 Prompt 模板库、三库元数据规范。
- 后续扩展：换模型后单次查询成本压至 ¥0.0024，三层回归零回归。

**交付物**：PRD（PDF）、Prompt 模板库、演示视频口播台本、面试讲述指南、`shopkeeper-agent/` 源码。

## 02 深度研搜 · 多智能体研究

针对开放式研究任务中信息源分散、长任务链路失控、结论无出处（散 / 断 / 黑盒）等结构性问题，以单智能体最小原型为基线，升级为「一主三分域」多智能体研究系统。通过行为合同、指标让步顺序与 PRD↔代码差距清单，把研究过程从不可观测的长任务升级为可计划、可溯源、可回滚的交付链路。

- **分域 Agent 与来源路由**：针对公开网络、结构化数据库、内部知识库、用户附件四类来源无法统一调度（散），通过主智能体规划 + 网络搜索 / 数据库查询 / RAGFlow 三个专家助手分工，将单次模型裸答升级为多来源、带来源 id 的证据汇总。
- **效果定义与让步顺序**：针对查得全就慢、查得快就可能没出处（指标打架），通过 9 指标因果链 + 四级让步顺序（底线 > 质量 > 可用 > 效率）+ 3 项一票否决，将模糊的「效果好」升级为冲突时可裁决的验收规则。
- **行为合同与可执行验收**：针对 LLM 输出格式漂移、结论无出处（漂 / 黑盒），通过五类 JSON 输出契约与 Eval Spec（70 条三层评测集、两段式门禁），将 Prompt 变更纳入生产变更门禁。
- **成本与风险的产品化约束**：针对补搜深度导致任务失控、断连与幻觉难归因（不可控 / 难归因），通过任务预算（300k token / 300s）、降级链 3 档、置信度三档与残余风险清单签字制，把限制做成刹车、把恢复做成安全带。
- **PRD↔代码对账机制**：针对 PRD 定义与工程实现之间的落差（不可审计），通过 15 条差距清单（编号与 PRD 正文一一对应）与上线准入清零规则，把「文档写完即结束」升级为持续对齐。

**成果**

- 已验证：上传校验与错误码契约 11/11 冒烟通过；差距清单 3 条已修复。
- 能力沉淀：9 章 + 2 挂靠章 PRD、Prompt Spec 行为合同、Eval Spec、四档成本预算、三阶段灰度与 4 条回滚条件。
- 口径说明：PRD 中完成率 / 时长 / 有据率等为**验收基线**，非实测达成值；Dify 单路 41.2s / 85,113 tokens 为实测锚点，仅作参照，不作线性外推。

**交付物**：PRD（PDF，含修订记录）、`deepsearch-agents/` 源码与架构图、系统真实生成的示例报告、PRD↔代码差距清单（prd-gap.md）。

> 说明：本项目技术实现基于开源教程 `ai-agents-from-zero` 的配套源码；我的贡献集中在产品侧——需求分析、PRD 全章定稿、指标与验收体系、边界与成本决策、上线灰度设计及差距清单管理。

## 03 企业招聘智能筛选

以企业招聘单点功能为切入点，针对 HR 筛简历靠经验、判定口径不一致、AI 结果不可直接采信（慢 / 偏 / 黑盒）等问题，按 F1 需求分析 → F2 MVP 开发联调 → F3 智能任务链 → F4 项目交付四阶段推进，建设「配置 — 分析 — 复核 — 判定」闭环的智能筛选工具。

- **岗位要求的配置化建模**：针对筛选标准散落在 HR 经验里（散 / 不可配置），通过技能标签（必须 / 加分）、约束边界、匹配阈值的结构化配置，将口头标准升级为可复用、可调参的岗位模型。
- **双引擎与异常兜底**：针对模型调用不稳定、空简历与低置信度样本（漏 / 错），通过规则算法作为默认引擎 + OpenAI 兼容接口预留 + 调用失败自动降级，将单点依赖升级为有兜底的分析链路。
- **人机协同复核机制**：针对 AI 结论直接生效带来的责任风险（不可审计），通过置信度分级、低置信度强制待复核、通过 / 淘汰 / 转复核判定与撤销，把自动化判定升级为可追溯、可回滚的决策闭环。

**成果**

- 已验证：32 条自动化测试覆盖接口、数据库、AI 客户端、规则打分与边界场景；可运行 MVP 与两套交互原型。
- 能力沉淀：F1–F4 四阶段实战报告（需求分析 → MVP → 任务链 → 交付）。
- 后续扩展：规则引擎与 AI 引擎解耦，替换模型不改动产品层判定逻辑。

**交付物**：F1 需求分析与原型实战报告、F2 MVP 实战报告 + 操作视频 + 可运行项目、F3 任务链材料、F4 项目交付包。

## 能力主线

三个项目不是三份 Demo，而是同一套方法在不同场景的复用：

| 从   | 到   | 产品机制                                |
| --- | --- | ----------------------------------- |
| 说不清 | 可验收 | 评测集、及格线、指标让步顺序倒推需求边界                |
| 不可控 | 有边界 | Prompt 行为合同：生成 / 澄清 / 拒答三形态 + 高风险阻断 |
| 黑盒  | 可归因 | 结果卡带 SQL、检索证据与置信度；badcase 回流评测集形成飞轮 |
| 拍脑袋 | 有依据 | 模型对照实验、成本预算、降级链与回滚条件                |

## 我定义什么 / AI 执行什么

| 由我定义（产品判断）           | 由 AI 与工程流水线执行    |
| -------------------- | ---------------- |
| 业务边界、不支持清单、非目标       | 代码生成、单元测试、环境搭建   |
| 指标体系、让步顺序、评测集与及格线    | 批量跑批、回归执行、结果统计   |
| Prompt 行为合同、拒答与高风险阻断 | Prompt 模板填充、格式校验 |
| 成本预算、降级链、灰度与回滚条件     | 日志埋点、监控面板、部署脚本   |
| PRD↔代码差距清单的裁决与签字     | 差距项逐条修复与复测       |
